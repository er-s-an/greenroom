The answer

Three deterministic gates.
The LLM only writes wording.

gate 1
Citation Gate
Every answer sentence anchors to one official source sentence and stays faithful to it — no flipped "not", no swapped "must", no changed number. Otherwise: deterministic escalation to a human.
gate 2
Approval Gate
The copilot drafts outreach to stalled participants — nothing is ever sent until a human organizer clicks approve. Failed sends retry; crash-interrupted sends are flagged, never silently repeated.
gate 3
Audit Trail
Every answer, refusal, conflict, draft, approval and send is an append-only record. Reports are computed from the trail — numbers you can reproduce by hand.
And when official sources disagree with each other, Greenroom fails closed: both sources verbatim, a human route — never a one-sided verdict.

Gate 1 — how the Citation Gate actually works

Deterministic. Per sentence.
Not prompt engineering.

retrieve
BM25 over the curated corpus of official documents
→
draft
LLM words an answer, near-verbatim, sentence-level citations
→
gate
every sentence anchors to one source sentence; polarity, modal & number signatures must match
→
decide
answered · escalated · conflicted
  • Merged citations can't smuggle violations — a flipped "never mandatory" hiding behind a faithful sentence is still caught; each claim sentence is anchored on its own.
  • Stale information never ships as current — a passed application deadline is acknowledged, not offered.
  • One repair pass with the gate's exact reasons — wording gets fixed; fabrications still escalate.

Gate 2 — stall radar behind the Approval Gate

Every participant is a state machine.
Every nudge waits for a human click.

registered
→
joined
→
introduced
→
active
→
submitted
  • Stall radar flags who is stuck where — never-joined, never-introduced, gone-quiet, missing-submission — and drafts a nudge matched to the reason.
  • Nothing sends itself — drafts sit in the approval queue until an organizer approves or rejects with a reason.
  • Honest delivery states — sent requires a real receipt; the demo sender is labeled simulated; failures land in send_failed and retry idempotently; a crash mid-send is recovered as "outcome unknown", never silently resent.

Architecture

All decisions deterministic.
Providers swap; permissions don't.

core — pure logic, zero I/O
  • BM25 retrieval · per-sentence citation gate
  • conflict scanner: detector proposes, human registry disposes
  • lifecycle state machine · stall rules · approval queue
  • append-only audit · deterministic report
edges
  • LLM — Kimi K2.7 hosted ⇄ deterministic offline mock, same gate
  • Server — Fastify API, JSON/JSONL persistence, atomic snapshots
  • Dashboard — React organizer workbench
  • Discord adapter — implemented (tri-state replies, DM receipts); live-guild pilot is next
Privacy is a feature: radar reads only public-channel metadata; outreach is opt-in and human-approved.
